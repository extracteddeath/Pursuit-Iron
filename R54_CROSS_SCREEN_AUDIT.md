# R54 — Cross-screen semantic state and phone consistency

## Why this exists
R53 made Home, Plan, Progress, Profile, Settings and full Program comparable in paired Rose dark / Rosewater light screenshots. R54 carries the same validation standard into Library, Exercise Detail and the resumed Workout and fixes a real selection-state inconsistency for programs whose progression is **manual**. This is an incremental architecture pass, not a rewrite of the workout logger or strength engine.

## Product change
- A manually progressing Program still lets the user preview/select Week 1–4. Previously the Program rail passed `active=false` for **every** week when `progression=manual`. The new `aria-pressed` attribute exposed by R53 therefore described every choice as off, and no week visually stood out.
- The selected week now uses the existing WeekPill active role even under manual progression, without changing what the week contains or how progression works. Other manual weeks remain deemphasized. No training prescriptions, user history, settings, exercise selection, persistence, target values, timers, steppers or completion behavior have changed.
- Build 833 advances the client shell. Offline version and module hashes are regenerated by `scripts/finalize-release.mjs` and verified before a merge.

## Scope of paired phone visual contract
`verification/r54-cross-screen-browser-test.mjs` uses a seeded program and real Chromium DOM with both **Rose dark** and **Rosewater light** themes, 393 × 852 CSS px. For each theme it captures:
- Exercise Library: filter/results screen, measurable page width and overflow
- Exercise Detail: real drawer destination and retained sizing
- Manual Program: exactly one visibly selected, 44px+ week; a tap moves pressed state to Week 2
- Resumed Workout: persisted live session and valid weight/reps input dimensions without horizontal overflow

Screenshots are `verification/r54-{library,detail,manual-week,workout}-{rose,rosewater}-phone.png` and are emitted in the existing browser integration artifact. Existing R53 tests continue to capture the six primary destinations and the Program's dynamic-progression rail. R36 verifies 20 saved palettes, and B825/other workout tests protect the complete set grid.

## Acceptance and caveats
Run canonical integrity, core contracts, independent engine audit, all four browser groups (17 browser contracts total), and main-branch post-merge CI. Visual screenshots are for review rather than automatic aesthetic certification. No claim of physical Android TalkBack, gesture, keyboard, font 200% or OLED color validation without device evidence. The remaining long-tail CSS contains older local aliases; avoid deleting them until computed-style parity and screenshot review prove redundancy.

Source decisions follow Android Material 3 semantic foreground/background pairings rather than per-screen hexes: https://developer.android.com/codelabs/m3-design-theming
