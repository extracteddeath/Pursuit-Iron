## Confirmed mismatches fixed in this candidate

**AUD-001 · Library filters — target 48px / observed 44px (P1 usability).**
- Main stylesheet specified `min-height:44px` for `.wpb-library .wpb-filter-chip` and `.wpb-library-flag`.
- A more-specific Expressive override separately enforced `min-height:44px!important`. Changing only the base rule would not work.
- This candidate updates **both** base and override to 48px, preserving selection semantics and scroll ownership.
- `verification/r54-cross-screen-browser-test.mjs` now measures actual visible filter geometry, checking both width and height against 48px before the existing scroll/back/filter sequence.

**AUD-002 · Workout completion recovery choices — target 48px / observed 44px (P1 usability).**
- `.wpb-finish-rating-choice` was `min-height:44px`.
- This candidate changes it to 48px; B994 now requires 48px for the selected recovery choice and all finish actions in its existing 320/393/834-width and enlarged-text checks.

## Confirmed debt and unverified risk register

**AUD-003 · CSS priority debt (P1 maintainability, *not* a proven visual regression).**
- Baseline `app.css` contains **2,035** `!important` occurrences over **10,131** lines (642,573 UTF-8 characters).
- `verification/ui-ownership-test.mjs` caps external priorities at **2,060**, app-embedded priorities at **1,053**, repeated property owners at **zero**, and scanned inline-style objects at **1,406**. These figures are limits, not current measured counts for every category.
- The design contract prohibits growing these ceilings. For future refactors, delete superseded declarations and reduce the ratchets; do not insert a new override at the end of the stylesheet.

**AUD-004 · Compact workout control touch targets (P1 investigate, no fix in this pass).**
- The stylesheet includes `.wpb-session-context>button` with `min-height:40px` and an Expressive Workout rest-action rule with `min-height:44px!important`.
- Whether these are justified documented dense exceptions with an alternate accessible control must be demonstrated. The design spec calls for 48px generally, so inspect the actual rest/action dock under 320px, 200% text, and keyboard before increasing sizes. A blanket change risks hiding the active logger.
- Do **not** interpret the CSS minima alone as proof of the effective rendered hit area; measure it.

**AUD-005 · Fresh visual evidence (P1 unverified).**
- Capture the exact Build 989 baseline and the audited candidate at 320/393/834/1280px, dark and light themes; include 200% actual text, short landscape and keyboard.
- Inspect first-viewport Home, Plan, Workout/Focus, Library, Progress, Profile, Settings and dialogs. Compare stable landmarks and no-occlusion regions; fixtures alone are not a hardware/visual sign-off.

**AUD-006 · Training/PR and live app continuity (P0 if failing, not currently alleged).**
- Require J1–J8 from spec §12, including genuine DP suggestions vs user-entered data, PR-once, cycle volume/exercise compatibility, history Undo, and offline/resume.
- Preserve `modules/workout-pr.js` and engine owners; visual changes must never mutate training facts.

**AUD-007 · Hardware acceptance (P1 open).**
- Physical Android IME/Back/TalkBack/gesture interruption, reduced motion changed mid-flow, and foldable layouts have not been certified by this source audit.

## Continuation — Pass 03: remove competing runtime theme geometry (design spec §§1, 4, 7, 11)

### Root-cause evidence
The design-spec 48px header controls were still rendered at **38–44px in Chromium at 320px**, and the Profile achievement disclosure at **46px**. This was a real cascade conflict, not an insufficient CSS selector: `modules/App.js` generated 40px header sizing with `!important`, plus a 38px media rule on small phones, and special-cased Finish with the fragile obsolete `[style*='width: 34']` check. The static `app.css` role alone could not prevail. A high-specificity Profile expressive rule similarly forced the disclosure down to 46px.

### Implemented one-owner correction
1. Retired obsolete generated CSS for Workout Leave, Focus, options, Finish, exercise rail sizing and the narrow-phone 38px exceptions. Existing `app.css` geometry (48px) now owns those controls. Respected the compact timer and meaningful selected/nonselected states without modifying logged sets, timers or handlers.
2. Removed the obsolete Profile 46px override; maintained its expressive corner shape, while the shared 48px base controls geometry.
3. Strengthened B831 Chromium measurement to include non-overlapping, viewport-contained Workout header targets, Program header targets and actual exercise rail button hitboxes at 320px/430px. Profile, Schedule and set-edit tests separately cover their own targets and scaling.
4. Ratcheted embedded stylesheet priority debt with a measured `MAX_APP_IMPORTANT = 1024` ceiling (previous ceiling 1,053); all covered source modules together contain **1,024** `!important` references at this candidate. This is a new enforced ceiling, not an aspirational number.
5. `app.css` remains **642,519 characters** (maximum **642,573**) and its 2,035 priority references did not grow. No new feature-specific override sheet or rival animation owner was added.

### Proof boundary and next UI work
The browser suite must pass on the final exact commit; results from earlier heads that failed or were canceled do not certify this candidate. Release, engine, physical-Android/TalkBack and offline checks remain separate release gates. Continue with the spec's first-screen Workout logger evaluation, real focus/IME geometry, Profile share-card morph, Settings value-entry and remaining cascade-debt reduction. Do not merge or increment the PWA build until the full combined verification is green.
